TL;DR. HaleBlocks is a small library (imported as hale_core) that provides the shared scaffolding for the Halo research projects: attention modules, transformer stacks, a plugin registry, strict pydantic YAML configs, and a bounded-storage sequential streaming loader.
  • Problem: Research projects that explore different architectures — LLMs, VLMs, world models, diffusion — duplicate training loops, config validation, and dataset streaming code.
  • Method: Plugin registries (@register_model, @register_loss, …) decouple components from the training loop. A YAML key selects any registered component at runtime.
  • Config system: Strict pydantic validation with inherits: — unknown fields are an error, not silently ignored. Single-field overrides without full repetition.
  • Stacks: GPTStack (causal), LGTStack (local-global + dual RoPE for diffusion), DiTStack (adaLN-Zero for world models).
  • Data: 33 SmolLM2 LLM datasets (15 pretrain, 14 SFT, 4 RL/DPO) in a typed registry alongside the VLM and VLA datasets used by Hale-VLM.

Problem Statement

A typical ML research group maintains separate training scripts for each project. When a new model arrives, someone copies the training loop, adds the new model class, renames some variables, and two months later there are three diverged copies of the same AMP + gradient-clipping + checkpoint-restore logic, each with its own bugs.

Config drift: Each project grows its own argparse or ad-hoc YAML reader. An unknown field is silently ignored; a wrong type becomes a runtime crash deep in training. Reproducing a run from a config file becomes unreliable.
Data streaming reinvented: Streaming 50+ HuggingFace datasets sequentially, prefetching the next while the current is playing, and capping storage — this is the same logic needed by every project, but it gets reimplemented each time.
Architecture fragmentation: Attention, FFN, and positional encoding appear in slightly different forms in each project's model file. Bugs fixed in one don't propagate; improvements don't share.

HaleBlocks solves all three by being the single authoritative implementation that every Halo project imports. New components register with a decorator; the training loop, config system, and data loader are shared without modification.

Method / Design

  1. Plugin registries

    Two registry types: NamedRegistry maps a string to a class or function; VariantRegistry also stores and validates a per-variant pydantic schema. Registration is a one-line decorator:

    @register_model("my_vlm")
class MyVLM(nn.Module):
    def __init__(self, cfg: MyVLMConfig): ...

    Lookup: MODELS.build("my_vlm", cfg). Unknown names raise immediately. New components in downstream projects (e.g. Hale-VLM) call register_vlm_plugins() once and then use HaleBlocks' Trainer unchanged.

  2. Config system

    Configs are pydantic v2 models. load_config(path) performs deep YAML merge (respecting inherits: base.yaml) and then validates the merged dict — unknown fields are a ValidationError, not silently discarded. Experiment output paths are computed deterministically from the config hash.

    ★ Reproducibility guarantee: Two configs that produce the same validated RunConfig object will produce the same experiment, because all randomness is seeded from config fields.

  3. Transformer building blocks

    build_attention(variant, n_heads, kv_heads, dim, …) returns MHA, GQA, or MQA attention with RoPE and the right causal / bidirectional / block-causal mask. FeedForward(variant, d_model, d_ff) returns MLP, GeGLU, or DeepSeekMoE FFN. Both are used directly in the three stacks:

    GPTStack — standard causal transformer (autoregressive LMs, policy heads). LGTStack — local-global attention with dual RoPE: short-range local heads (window $w$) + long-range global heads, both operating on the same hidden states. Designed for masked diffusion and flow matching where bidirectional context matters at all scales. DiTStack — adaLN-Zero conditioning: each block computes $(\gamma, \beta, \alpha)$ from a conditioning vector $c$ via a linear projection, then modulates layer norms and residual gates.

  4. Sequential streaming loader

    Given a list of dataset specs (HuggingFace paths or local directories), SequentialMultiDatasetStream plays each dataset up to a configurable cap while a background thread warms up the next. Peak RAM is bounded to roughly one dataset at a time — no need to download 50 datasets before starting training.

    Supports VLM samples (image + prompt + response), LLM samples (text chunks), and VLA robot samples (image + action trajectory + annotation).

  5. Trainer loop

    The shared Trainer handles: AMP (bfloat16/float16), configurable gradient accumulation, gradient norm clipping, LR scheduling (cosine + warmup), TensorBoard and W&B logging, and full-state checkpoint save/restore (model + optimiser + AMP scaler + step count). Each downstream project passes its own loss function; the trainer calls loss_fn(batch, model_outputs) with no further assumptions.

Quick Start

  1. uv add "hale-blocks @ git+https://github.com/basaanithanaveenkumar/HaleBlocks"
# or editable:
uv add --editable /path/to/HaleBlocks
  2. from hale_core.nn.layers import build_attention, build_attn_mask
from hale_core.nn.stacks import LGTStack
from hale_core.registry import register_model, register_loss
from hale_core.config import load_config

@register_model("my_model")
class MyModel(nn.Module):
    def __init__(self, cfg):
        self.stack = LGTStack(cfg.n_layers, cfg.d_model, cfg.n_heads)

cfg = load_config("configs/my_experiment.yaml")
  3. # Stream SmolLM2 SFT datasets (1000 samples each, background prefetch)
from hale_core.data import build_llm_dataloader
for sample in build_llm_dataloader(stage="finetune", samples_per_dataset=1000):
    print(sample.dataset, sample.prompt[:60])

Limitations & Ethical Considerations

Stub

Distributed training

DDP support is a stub. Multi-GPU training requires wrapping the model externally with torch.nn.parallel.DistributedDataParallel.

Missing

Flash Attention

Attention uses standard F.scaled_dot_product_attention. Flash Attention 2 integration (via flash-attn package) is not yet wired up.

Open

Dataset licences

The 33 LLM datasets and 540 VLA datasets registered in HaleBlocks have varied licences. Users are responsible for checking and complying with each dataset's terms before commercial use.

Pending

PyPI release

Only available via git install. A versioned PyPI package with pinned dependencies is pending.
